## Copy or transfer

Values sent to a worker are copied by default. For a large `ArrayBuffer` that means allocating the same memory
twice. A **transfer** moves ownership instead: the receiving thread gets the memory, and the sender is left with
an empty buffer.

`ArrayBuffer`, `MessagePort`, `ImageBitmap`, `OffscreenCanvas` and streams are
[transferable](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Transferable_objects).

## From the worker back to the main thread

A returned value is always copied. To transfer a result, complete the call yourself and pass the transfer list
to `message.resolve`.

<CodeBlock code={imagesWorker} lang="ts" title="images.worker.ts" />

`reject`, `cancel` and `reportProgress` accept a transfer list too.

<Callout type="warning" title="A transferred buffer is gone for the sender">
  After a transfer, `buffer.byteLength` is `0` on the side that sent it, and reading it throws. Read what you
  need before the call, or use the buffer that comes back.
</Callout>
