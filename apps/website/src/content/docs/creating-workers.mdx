## Every source

`createWorker`, `createEasyWebWorker` and `new EasyWebWorker(...)` accept the same sources. Pick the one that
fits how your project builds and serves its workers.

| Source              | Best for                                        | Pool with `maxWorkers` | `reboot` / `force` |
| ------------------- | ----------------------------------------------- | ---------------------- | ------------------ |
| `URL` or `string`   | Worker files built by your bundler              | Yes                    | Yes                |
| Existing `Worker`   | Bundlers that detect `new Worker(new URL(...))` | One Worker             | No                 |
| Existing `Worker[]` | Bringing your own pool                          | The array is the pool  | No                 |
| Function            | Workers with no file at all                     | Yes                    | Yes                |
| Function array      | Workers composed from reusable pieces           | Yes                    | Yes                |

## A native Worker you create

webpack 5, Parcel and Vite all detect the expression `new Worker(new URL(...))` and bundle the file. Create the
Worker that way and hand it over.

<CodeBlock code={native} lang="ts" title="main.ts" />

The library cannot create that Worker again, so `reboot` and `force` are not available. Leave `keepAlive` at its
default, so the Worker is not terminated when idle.

## Cleanup

Dispose the worker when the feature that owns it goes away:

```ts
await unwrap(math).dispose();
```

`dispose` cancels the pending calls, revokes the generated worker URL when there is one, and terminates the
Workers.
