## Three ways to write a method

<CodeBlock code={threeWays} lang="ts" title="worker.ts" />

| Style                                         | Completes the call      | Types                             |
| --------------------------------------------- | ----------------------- | --------------------------------- |
| Plain function                                | With the returned value | Inferred                          |
| `onMessage((payload, message, event) => ...)` | With the returned value | Inferred, `message` typed         |
| `onMessage<P, R>().handle((message) => ...)`  | You do                  | Explicit, `message.resolve` typed |

All three are called the same way from the main thread.

- Use a **plain function** when the method only needs its payload.
- Use **`onMessage`** when it also reports progress or reacts to a cancellation. The wrapper exists to give the
  second parameter its type; a plain function receives the same arguments.
- Use **`onMessage().handle`** for timers, streams and event-based APIs, or to
  [transfer a result](../transferable-objects/).

<Callout type="note" title="The call is completed once">
  If a method completes the message itself with `resolve`, `reject` or `cancel`, its return value is ignored.
</Callout>

## The message

Available as second parameter of a method, in `.handle(...)`, and in the [message API](../message-api/).

| Member                                            | Purpose                                       |
| ------------------------------------------------- | --------------------------------------------- |
| `payload`                                         | Value sent from the main thread               |
| `resolve(result?, transfer?)`                     | Resolves the call                             |
| `reject(reason?, transfer?)`                      | Rejects the call                              |
| `cancel(reason?, transfer?)`                      | Cancels the call from inside the worker       |
| `reportProgress(percentage, payload?, transfer?)` | Reports progress and keeps the call pending   |
| `onCancel`, `onResolve`, `onReject`, `onProgress` | Subscribe to each outcome; return unsubscribe |
| `onFinalize`                                      | Runs once the call ends, whatever the outcome |
| `isPending()`, `getStatus()`                      | Current state of the call                     |

## The event

The third parameter of a method is the original `MessageEvent` received by the worker. It is rarely needed; it
is there for code that inspects the raw message.

## The controls behind the methods

The object returned by `defineWorker` describes the methods. `unwrap` reaches the worker behind it: `onMessage`
