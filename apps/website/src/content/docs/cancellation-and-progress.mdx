## Progress on the same call

Every call returns a `CancelablePromise`. Progress and cancellation belong to that promise, not to a second
channel.

`reportProgress(percentage, payload?)` can also carry a value. It arrives as the second argument of the
`onProgress` callback.

## Cancellation reaches the worker

`task.cancel(reason)` sends the cancellation to the worker, and the promise rejects with that reason once the
worker confirms. Inside the worker there are two ways to notice it:

- `message.isPending()` becomes `false`. A loop can check it between chunks, as above.
- `message.onCancel(callback)` runs the callback. Use it to abort requests and release resources.

<CodeBlock code={onCancel} lang="ts" title="search.worker.ts" />

Cancellation is idempotent: canceling twice sends one request to the worker, and canceling a call that already
finished does nothing.

## Stop work that never pauses

<Callout type="warning" title="A blocked worker cannot hear a cancellation">
  A cancellation is a message. A worker in the middle of a synchronous loop cannot receive messages, so
  `task.cancel()` has no effect until the loop ends. Break long work into chunks and pause between them, as
  `findPrimes` does.
</Callout>

For work that cannot pause, restart the worker instead:

<CodeBlock code={force} lang="ts" title="controls.ts" />

`force: true` terminates the Workers, rejects every pending call and starts fresh ones. A worker created from an
existing native `Worker` cannot be restarted by the library; see [Creating workers](../creating-workers/).
