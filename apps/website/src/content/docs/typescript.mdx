## One type crosses the threads

The worker file exports the type of what `defineWorker` returns. That type is the only thing the main thread
imports.

<CodeBlock code={mathWorker} lang="ts" title="math.worker.ts" />

Use `import type`, so the bundler never pulls the code of the worker into the main bundle.

## The message in a plain function

A plain function receives the message as second parameter, but TypeScript cannot infer its type there. Either
wrap the method with `onMessage`, or annotate it with `WorkerMethodMessage<TPayload>`.

<CodeBlock code={annotate} lang="ts" title="counter.worker.ts" />

<Callout type="note" title="Why resolve is loose there">
  In a method that returns its result, the result type comes from the function body, so the message cannot know
  it yet: `message.resolve` accepts `unknown`. Use `onMessage<TPayload, TResult>().handle(...)` when you need a
  typed `resolve`.
</Callout>

## Good to know

- **`strict`**: required payloads are enforced with `strict` or `strictNullChecks`. Without it, every payload is
  optional.
- **Rejections are `unknown`**: the reason of a rejected or canceled call is typed `unknown`. Narrow it before
  reading it.
- **One name is taken**: a method cannot be called `then`. The worker object is not a promise, so `await worker`
  never sends a message.
- **Merged workers**: with an array of functions, write the array inline or declare it `as const`, so each
  function keeps its own type.
